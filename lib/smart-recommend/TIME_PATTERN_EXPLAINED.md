# 时间模式维度详解

## 用户的问题

> "时间模式是怎么定义的？用户不是什么都还没有输入啊？"

这是一个非常好的问题！让我们详细解释这个维度的工作原理。

---

## 核心概念

### 问题澄清

当系统**生成推荐**时，用户确实可能还没有输入任何新任务。但系统有用户的**历史任务数据**。

### 时间模式的本质

"时间模式"不是对用户未来输入的预测，而是：
> **将历史任务的时间与当前时间进行匹配，找出用户习惯在当前时间段做的任务**

---

## 完整工作流程

### 1. 推荐生成的起点

系统从以下来源生成推荐：

**A. 历史任务复现**
```
用户历史任务 → 去重 → 评分 → 推荐给用户
```

**B. 周期性任务预测**
```
识别周期性模式 → 预测下次出现 → 推荐给用户
```

### 2. 历史推荐的时间模式计算

当处理历史任务时：

```typescript
// 假设当前时间是 14:30（下午 2:30）
// 用户有一个历史任务：

历史任务 = {
  title: "数学学习",
  startTime: "15:00",  // 下午 3 点
  // ... 其他字段
}

// 计算时间模式得分：
任务小时 = 15
当前小时 = 14
小时差 = |15 - 14| = 1
得分 = 1 - 1/6 ≈ 0.833
```

**关键理解**：
- 这个任务的时间是**历史记录**，不是用户新输入的
- 我们在计算："如果现在推荐这个任务，它的时间与当前时间匹配吗？"

### 3. 预测推荐的时间模式

对于周期性预测的任务：

```typescript
// 假设系统检测到用户每周一 19:00 去运动
// 今天是周一，当前时间 18:30

预测任务 = {
  title: "跑步",
  predictedStartTime: "19:00",
  // ...
}

// 预测推荐中，时间模式被设置为固定值 0.6
// 因为这是基于周期模式的预测，我们认为时间是合适的
```

## 具体示例

### 场景：周三下午 14:00

**用户历史任务**：

| 任务 | 开始时间 | 标题 |
|------|----------|------|
| 1 | 09:00 | 英语阅读 |
| 2 | 10:30 | 数学练习 |
| 3 | 14:30 | 编程学习 |
| 4 | 16:00 | 运动健身 |
| 5 | 19:00 | 晚餐准备 |

**当前时间**：14:00（周三下午）

**计算各历史任务的时间模式得分**：

| 任务 | 开始时间 | 小时差 | 时间模式得分 |
|------|----------|--------|--------------|
| 英语阅读 | 09:00 | 5 | 1 - 5/6 ≈ 0.167 |
| 数学练习 | 10:30 | 3.5 → 3 | 1 - 3/6 = 0.5 |
| 编程学习 | 14:30 | 0.5 → 0 | 1 - 0/6 = 1.0 |
| 运动健身 | 16:00 | 2 | 1 - 2/6 ≈ 0.667 |
| 晚餐准备 | 19:00 | 5 | 1 - 5/6 ≈ 0.167 |

**结果**：
- "编程学习"得分最高（1.0），因为它的时间最接近当前时间
- 系统会优先推荐这个任务，因为用户习惯在下午这个时段编程

---

## 为什么这样设计？

### 1. 利用用户习惯

用户往往有固定的作息习惯：
- 早晨学习
- 下午工作
- 晚上运动或休息

通过时间模式匹配，系统可以推荐符合用户生物钟的任务。

### 2. 上下文感知

当前时间本身就是重要的上下文：
- 工作日早晨 vs 周末下午
- 假期 vs 工作日
- 一天中的不同时段

### 3. 即时性

推荐的任务应该是"现在就可以开始做"的，或者"很快就该做"的。

---

## 两种推荐类型的对比

### 历史推荐

```
有历史任务 → 有历史时间 → 计算与当前时间的匹配度
```

- 使用真实的历史任务时间
- 动态计算得分
- 时间差异 < 6 小时都有得分

### 预测推荐

```
基于周期模式预测 → 预测时间 → 使用固定得分 0.6
```

- 时间是预测的
- 使用固定值（因为预测本身已经考虑了时间）
- 依赖周期性模式的置信度

---

## 实际应用场景

### 场景 1：工作日早晨 8:00

用户历史中有：
- 08:30 晨读
- 09:00 工作准备

时间模式得分会很高，系统会推荐这些任务。

### 场景 2：周五晚上 20:00

用户历史中有：
- 20:00 看电影
- 21:00 阅读

这些任务的时间模式得分会很高。

### 场景 3：任何时间，任务无开始时间

如果历史任务没有记录开始时间：
- 时间模式得分 = 0.3（默认值）
- 依赖其他维度（标签、周期性等）

---

## 总结

### 关键点

1. **不需要用户新输入**：使用历史任务数据
2. **匹配当前时间**：计算历史任务时间与现在的接近程度
3. **反映用户习惯**：找出用户习惯在当前时段做的任务
4. **两种方式**：
   - 历史推荐：动态计算真实匹配度
   - 预测推荐：使用固定值（依赖周期性）

### 类比

就像一个了解你习惯的朋友：
- 知道你下午喜欢学习
- 现在是下午
- 推荐"你要不要开始学习了？"

这就是时间模式维度的作用！
